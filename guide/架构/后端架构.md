# 后端架构（宿主侧）

> dsh 没有传统独立后端服务：宿主侧 = Cordis 插件树在 Node 中的运行时（CLI profile 启动）。本文件描述宿主侧组合与核心包；类型定义归 `../docs/subsystems/`，包契约归各包 README。

## 组合模型

- 一切皆插件：模型适配器、工具注册表、会话日志、agent loop 都是可替换插件，无特权核心。
- profile：命名组合，存于 Harness home，列出堆叠的 bundle、树外插件与用户 `cordis.patch.yml`；出厂模板 web / headless / sdk / sdk-minimal / acp。
- bundle：Cordis 配置行及其挂载代码的分发格式；`dsh-base` 是 web/headless/sdk/acp 的共享首层，web-app / headless / sdk-app / acp-app 各自追加应用层。
- 分层顺序：profile 的有序 bundles → profile 的 `cordis.patch.yml` → home patch → `--patch` overlay；preset patch 在声明的 `config.plugins` 内应用同样优先级。
- HMR：base 启用配置级 dsh-hmr，headless/sdk/acp 禁用，sdk-minimal 不含。

## 启动

- 支持的 Node 应用只能经命名 dsh profile 启动（`dsh --profile <name>` 或 `dsh <name>`）；package bin、demo、公开 SDK argv 逃逸均被禁止，`verify-application-entrypoints` 强制。
- 查看本机启动的插件树：`dsh --profile web --dump-config`。

## 核心包（ctx 键）

| 包 | 职责 | ctx 键 |
|:--|:--|:--|
| `packages/core/session` | 追加式 SessionEvent 日志与内存存储 | `ctx.sessions` |
| `packages/core/system-prompt` | prompt 段与工具 schema 组装 | `ctx.systemPrompt` |
| `packages/core/tools` | 作用域化工具注册表与受保护执行管线 | `ctx.tools` |
| `packages/core/agent` | Agent 接口、实时注册表、agent/* 事件 | `ctx.agents` |
| `packages/core/agent-loop` | 默认驱动实现 | `ctx.agentLoop` |
| `packages/llm/llm` | 消息与流词汇表、适配器 seam | `ctx.llm` |

## 事件模型

- Session events：持久事实，追加到日志并经 `session/event` 广播；需跨重载存活时使用。
- Agent events（`agent/*`）：携带实时 Agent（inbox、step、status、request、validation、continuation）；观察或拦截进行中的工作时使用。
- Capability events：为 seam（`fs/*`、`tools/*`、`telemetry/*`）挂载策略与适配器，不导入 loop。

## 轮次流程（turn/step）

step = 一次模型请求及其工具调用；turn = 零个或多个 step，首个输入被认领前打开，无欠付时关闭。完整时序图见 `../docs/architecture.md`「Turn flow」。

## 持久化与兼容

- 公开 API 处于 pre-stable；变更需同步所有消费者。
- SQLite 使用单调 `SCHEMA_VERSION`；Session 格式版本遵循 `../docs/session-format-status.md`。
- 更多：`../docs/architecture.md`、`../docs/cordis-primer.md`、`../docs/subsystems/`。
